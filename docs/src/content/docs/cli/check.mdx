## What it checks

### Unpinned migrations

Reports any migration that has an `up.sql` but records no pin. A `lock.toml` that exists only to declare variables still counts as unpinned, since it pins nothing. Unpinned migrations are not reproducible because they resolve components from the current working tree rather than from a pinned snapshot.

To fix, pin the migration using [`spawn migration pin`](/cli/migration-pin/):

```bash
spawn migration pin <migration-name>
```

### Unreadable lock files

Reports any migration whose `lock.toml` cannot be parsed, along with the parse error. One unreadable file is a warning against that migration rather than a failure of the whole command, so every other migration is still reported.

## CI/CD

A non-zero exit makes `spawn check` suitable as a pipeline gate:

```yaml
# GitHub Actions example
- name: Check migrations
  run: spawn check
```
