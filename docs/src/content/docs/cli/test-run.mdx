Executes one or all tests against the configured database and displays the results.

## Arguments

- `<name>` — Specific test to run.

## Behavior

Runs the SQL for the test against the database, showing the transcript from that test.

## Diagnostics

Engines capture results and diagnostics (`NOTICE`, `WARNING` and error messages) separately, then flatten them into a single transcript: the results first, then any diagnostics beneath a separator line.

```
 ok 
----
  1
(1 row)

--- diagnostics ---
NOTICE:  table "nonexistent_table_xyz" does not exist, skipping
```

The separator and everything under it are omitted entirely when a test produces no diagnostics, so transcripts of clean runs contain results only.

Diagnostics are appended rather than interleaved because psql buffers its two output streams independently — results are block-buffered, diagnostics are not — so their relative order changes with the size of the output and cannot be reproduced. Appending is what makes the transcript stable enough to compare. The cost is that a diagnostic no longer sits next to the statement that produced it; a test that needs that context can mark the position itself with `\echo`.

Engines that produce a single ordered stream do not split at all, and their transcripts never carry a separator.

## Secrets

`test run` always masks `secret()` values, even though it executes the rendered SQL against the database, so secrets cannot leak through test output. See the [Secrets guide](/guides/secrets/#masking) for details.

## Examples

Run a specific test:

```bash
spawn test run user-creation
```
