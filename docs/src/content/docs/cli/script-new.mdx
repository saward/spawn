Creates a new script folder with a starting `script.sql`.

## Arguments

- `<script>` — Required. Name of the script, as a path relative to the scripts folder. May nest, e.g. `maintenance/reindex`.

Unlike [`spawn migration new`](/cli/migration-new/), the name is used as given — no timestamp prefix. Scripts are neither ordered nor applied once, so there is nothing for a timestamp to sequence.

Creating a script that already exists is an error rather than an overwrite, since the existing one may already have been run.

## What gets created

```
scripts/maintenance/reindex/
  script.sql
```

The starting `script.sql` wraps an empty body in `BEGIN;` / `COMMIT;`. Delete those two lines for statements that cannot run inside a transaction, such as `CREATE INDEX CONCURRENTLY`.

To use your own starting content instead of the default template, set [`template_script`](/reference/config/#template_script) in `spawn.toml` to a path (relative to `spawn_folder`) of a file to copy into `script.sql`.

A `config.toml` appears alongside it once you run [`spawn script pin`](/cli/script-pin/), or once you write one yourself to [declare variables](/cli/script-run/#declared-variables). Either is optional, and one does not imply the other.

## Examples

```bash
spawn script new reset_demo_data
spawn script new maintenance/reindex
```
